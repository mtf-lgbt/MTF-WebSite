## 前言

欢迎来到 MTF.LGBT 使用手册。MTF.LGBT 是一个面向跨性别群体的公益项目，希望为大家提供域名、邮箱、内容发布与交流等力所能及的服务。本手册汇总了目前常见功能的申请与使用方法，包括三级域名申请、邮箱注册、文章与 Subtitle 投稿、RSS / 邮箱订阅、翻译贡献、友情链接、Bug 提交、Pull Request 提交以及合作事宜等。

如果你是第一次来到这里，可以先按目录找到自己需要的部分；如果你已经使用过部分服务，也可以把本手册当作一份随时查阅的说明。由于项目由站长和志愿者维护，域名续费、邮箱等基础设施都依赖赞助和有限资源，因此请按需申请、合理使用。域名申请、文章投稿等内容通常需要审核，请耐心等待，避免重复提交。

手册内容会随着网站功能更新而调整。若手册与页面实际情况不一致，请以网站实际页面和 Issue 中的回复为准；尚在改造或未完成的功能，也会在对应章节中标注说明。遇到问题时，建议先阅读相关章节，若仍未解决，再到 GitHub Issue 中提问，并尽量附上截图、链接和复现步骤。

感谢每一位使用、投稿、翻译、反馈和赞助的朋友。希望这份手册能帮你更顺利地使用 MTF.LGBT，也欢迎更多人一起参与维护，让这里成为对跨性别者真正有用的空间。

## 三级域名申请

> 目前已知的情况是：CloudFlare免费版无法添加三级域名，若需要添加CloudFlare请单独寻求客服，可能会产生订阅费用。目前来说dnspod能够使用，但需要主域名验证。可能需要更多交涉。其他DNS服务商暂未测试。

mtf.lgbt三级域名采用申请制，请在网站[issue](https://github.com/mtf-lgbt/MTF-WebSite/issues)中添加issue。  
具体为点击右上角绿色的New issue按钮

![New issue 按钮位置](https://github.com/user-attachments/assets/48601684-c876-4704-b6fa-a53741e31222)

随后在弹出的页面中点击domain apply这个选项。随后根据引导将相关选项填入即可。这之中可能只有第三个引导问题较为难以理解。一般来说，您若想使用一个域名，就需要一个dns服务商。你在申请时需要让你的域名提供商给你**两个**Dns服务器地址。注意是两个。一般情况下，你直接将这两个地址填入到这一栏之中即可

### 翻译
> 这一段比较重要，我会在README.md中也写明。

首先很感谢您为我们的项目提供翻译，我们的翻译系统结构分为两个部分：词条翻译和内容翻译。

词条翻译和内容翻译的区别：

| 项目 | 词条翻译 | 内容翻译 |
| --- | --- | --- |
| 描述 | 对于标题、按钮文字、链接文本等内容采用原生的i18n国际化模组进行翻译。基本不会进行修改 | 对于长文、活动、通知等不方便放入JSON档案的文字，会采用内容翻译。比如「关于我们」页面。修改频率相较于词条翻译会多一些 |
| 特性 | 翻译内容严格一一对应，不过如果你发现一个文件塞了太多内容，你可以将一部分词条拆出来放在单独的文件里。（站长警告你别拆的太抽象别人看不懂） | 不同语言可以写完全不一样的文字，甚至可以添加区域性的活动通知。有点不像是单纯的翻译了，更像是区域设置。只不过这个「区域设定」会随着翻译设置的变化而变化，而不是平时我们见到的语言是一个设置项目，区域一个设置项目 |
| 位置 | ```./src/i18n``` | ```./src/routes``` |

#### 词条翻译

首先我们可以学习一下目前（2026-10-24）的目录结构：
```dash
src/i18n
├── i18n.js
├── ja
│   ├── blogs.js
│   ├── friends.js
│   ├── home.js
│   └── master.js
└── zh-cn
    ├── blogs.js
    ├── friends.js
    ├── home.js
    └── master.js
```
在这之中，```i18n.js```充当一个注册机，基础翻译工作在这里汇总。

##### 注册

首先需要在顶部import一个根文件，作为你语言翻译的起点。一般情况下根文件位置应该创建在```src/i18n/<Language Code>/master.js```。   
随后，你需要在message中加入你刚才import的名字，比如你如果写的是```import enus from './en-us/master.js'```，在message上就要写```enus```。

##### 架构

没有什么好说的，照着其他语言的架构抄就可以。只有一个重点需要注意下：

这是根文件的基础架构
```js
const zhcn = {
    { ··· }
}
export default zhcn;
```
你只需要保证「const」后面的那个单词以及「default」后面的那个单词是一致的，并且和```i18n.js```中相应import的名字一致就可以。

#### 内容翻译

这一段比较简单，在```/src/routes/```中创建一个文件夹（如果还没有人翻译），在文件夹内创建你要翻译的页面的名字加```.md```——比如「关于我们」页面需要创建```about.md```。但是有一个特例，就是主页，或者一般程序语境下的「index」。你需要创建```home.md```而不是```index.md```。

另外，你在创建文件夹时文件夹名称应该是```src/i18n/i18n.js```中import语言根文件时的名字。

至于如何写，直接参考[vitepress的wiki](https://vitepress.dev/guide/getting-started)，因为相关插件就是把它当vitepress来处理的，即便这个项目是个正经的Vue项目。
